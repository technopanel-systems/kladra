TITLE: Zeigarnik Effect
CATEGORY: Feedback
URL: https://designmotionhq.com/patterns/zeigarnik-effect

PROBLEM: The brain keeps unfinished tasks in active memory and drops finished ones immediately, so a 100%-complete checklist gives users no reason to return while a visible, meaningful gap keeps pulling them back.

RULES:
- Unfinished tasks hold outsized weight in memory ("active memory") while completed ones are dropped the moment they close. Sheet demonstrates with two to-do items: a completed "Sign-up for newsletter" recalled 0 times vs. an incomplete "Finish your portfolio bio" recalled 10, then 11 times — captioned "incomplete = 2x memory weight."
- A progress meter/checklist stuck below 100% creates return pressure; a fully checked-off 100% state removes any reason to come back. Sheet's onboarding example shows a "Set up" checklist (Verify email, Add profile photo, Pick a workspace done; Invite a teammate, Connect calendar left unchecked and highlighted red) captioned "user: returns daily," followed by the line "100% complete? You forget. 80%? It nags."
- In onboarding specifically, deliberately leave 1 box unchecked (sheet's literal instruction: "Leave 1 box unchecked") so the visible gap nudges the user to return and finish setup rather than the flow vanishing once "done."
- Profile-completion meters are the mainstream version of this: sheet shows a LinkedIn-style profile card (Marie Rousseau, Senior Product Designer) with a "Profile strength 80%" bar and an "Add 3 more skills" prompt, captioned "big tech runs on this... your profile is 80% done" — the pull is a persistent, low-friction nudge, not an interruption.
- The effect only fires for outcomes the user genuinely wants — sheet frames this as "one critical catch: outcomes, not chores," contrasting a "wrong fit" example (a newsletter-signup / "discover new collection" progress nag — captioned "user doesn't want to finish, just noise") against a "right fit" example (a course: "React Fundamentals, Module 4 of 5 — Hooks deep dive," 80% progress toward an actual certificate — captioned "user wants the cert. Loop pulls."). A manufactured progress bar on something nobody asked for (e.g. a marketing-email "reading progress" bar) creates zero pull.
- Model the mechanic as a three-step loop: Open Loop → Pull → Return (shown as three tags in the closing frame), and the design instruction is explicitly "don't close the loop, leave it open."

DO / DON'T:
- Do: leave a visible, meaningful gap — an unchecked box or an 80% meter — to invite the user back.
- Do: tie the unfinished progress to an outcome the user genuinely cares about (e.g. a certificate, a working profile).
- Do: keep the remaining percentage or remaining step salient so the open loop stays top of mind.
- Don't: close every loop at 100% — it removes any reason to return.
- Don't: manufacture progress on a chore nobody asked for (e.g. a fake reading-progress bar on a marketing email).

KLADRA: Applies narrowly and should be applied carefully. Legitimate uses: an onboarding/setup checklist for a new team member (Jerom's 14-person team) — e.g. "profile set up · notification preferences · first record created" — could leave one step visibly open to encourage completion, provided the outcome is something the user (Faisal, Rawan, Abdulrahman) actually wants, not manufactured busywork. A record's completeness (e.g. a quotation missing a required field, a project missing a dispatch date) could use the same "outcome, not chore" framing if the CRM already flags incomplete records — this is really just a variant of a required-field/validation indicator, reframed through this psychological lens. CONFLICT: Kladra explicitly bans "no number tickers or looping motion (skeletons do not pulse)" — a persistent nagging 80%-done meter that pulses or animates to draw attention would directly violate this; any implementation must be a static, calm indicator (a number/badge with a word, matching "every state has a word, never colour alone"), never an animated or looping nag. Also flag: this pattern is inherently a manipulation/engagement technique from consumer/growth products (profile-completion meters, course-progress nags) — Technopanel is a 14-person B2B operations tool, not a consumer app competing for engagement, so the "outcomes, not chores" caveat is doing a lot of work here: only apply this where leaving something open genuinely helps the business (an unfinished quotation, an incomplete record) — never to manufacture engagement for its own sake, which would be inconsistent with Kladra's plain, utilitarian tone.

PRIORITY: low — the underlying psychology is sound but Kladra's actual use cases for it are narrow (onboarding checklist, record-completeness indicators) and the closest tempting implementation (an animated completion meter) directly conflicts with the standing "no looping motion" rule, so this needs restraint rather than broad application.
