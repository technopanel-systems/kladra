TITLE: Navigation Patterns
CATEGORY: Navigation
URL: https://designmotionhq.com/patterns/navigation-patterns

PROBLEM: Teams pick a navigation pattern by taste rather than by platform and hierarchy depth, most commonly hiding primary navigation behind a hamburger menu, which measurably tanks engagement.

RULES:
- Five patterns form one system, chosen by platform and content depth, not preference: bottom tabs, persistent sidebar, hamburger/hidden menu, command palette, breadcrumbs.
- Bottom tabs: the mobile default — 3-5 top-level destinations, always visible, sit within thumb reach. Burying those same links in a hamburger on mobile drops engagement by ~40%.
- Persistent sidebar: the desktop answer for hierarchical content with 5+ sections — must stay in view; collapsing it by default kills discoverability of what's inside.
- Hamburger/hidden menu: secondary navigation only, never primary. Acceptable for secondary/mobile items, but hiding primary nav behind a hamburger on desktop drops engagement by ~56% (worse than the mobile case).
- Command palette (Cmd+K): a search-driven accelerator for power users — must be paired with visible nav, never the sole path to a feature, because new users don't know it exists.
- Breadcrumbs: only earn their place when the hierarchy is deeper than 2 levels; on flat structures they add visual noise instead of helping orientation.
- Choose by platform and depth, not taste — this is framed explicitly as one system with five components, not five interchangeable stylistic options.

DO / DON'T:
- Do: match the pattern to the platform — bottom tabs on mobile, a persistent sidebar on desktop.
- Do: keep primary destinations visible — 3-5 for tabs, 5+ sections to justify a sidebar.
- Do: reserve breadcrumbs for hierarchies deeper than two levels.
- Don't: hide primary navigation in a hamburger — engagement drops 40-56% depending on platform.
- Don't: make a command palette the only path to a feature; new users won't discover it.
- Don't: add breadcrumbs to a flat structure where they're just visual noise.

KLADRA: Maps directly onto Kladra's shell nav and the "search palette" CLAUDE.md already names as a surface. Concrete application: (1) Kladra's top-level sections (companies, projects, quotations, dispatches, team/reports, admin — roughly 5-7 destinations for 4 personas) fit the "5+ sections → persistent sidebar" rule on desktop (1366px) — sidebar should stay visible, not collapse by default, which also matches CLAUDE.md's explicit "no density toggle (one setting for fourteen people)" spirit of not hiding chrome behind a toggle; (2) on the 375px phone layout (reps in the field, per CLAUDE.md), primary destinations should become bottom tabs capped at 3-5, not a hamburger — this is a concrete, numbers-backed argument (40-56% engagement drop) for avoiding a hamburger as primary mobile nav for Faisal; (3) if Kladra has or plans a command palette (Cmd/Ctrl+K) it must stay a power-user accelerator alongside full visible nav, never the only way to reach a page — matches the rule precisely; (4) breadcrumbs only belong where Kladra's hierarchy actually runs 3+ levels deep (e.g. Company → Project → Quotation), not on flatter list screens, so a blanket breadcrumb bar everywhere would be noise per this rule. RTL note (not in the source pattern but required by Kladra): sidebar and breadcrumb direction must mirror in Arabic via logical CSS properties, and Cmd+K should probably read as Ctrl+K or a locale-appropriate shortcut hint. No conflict with any standing Kladra decision — navigation shape is orthogonal to drag-and-drop, bulk edit, saved views, comments, motion timing, or gradients.

PRIORITY: high — this defines the shape of Kladra's entire shell navigation across desktop and the 375px phone layout for both locales, and the specific engagement-drop numbers make a strong, concrete case against a hamburger-first design for a small team that needs speed, not menu-hunting.
