TITLE: Reverse-Engineered Linear
CATEGORY: Visual
URL: https://designmotionhq.com/patterns/reverse-engineered-linear

PROBLEM: Linear's interface feels expensive without any obvious "designed" flourish, and most teams can't name what specifically produces that feeling — so they either over-decorate or copy the wrong details.

RULES:
- Density reads as competence: 13px text, 32px row height, and letter-spacing pulled in by 1% (roughly -0.01em) let the same viewport show far more rows with no scroll. Sheet quantifies this directly — 8 issues visible loosely spaced vs 14 rows at the same height once density is applied, captioned "13px · 32px rows · -0.01em."
- Depth comes from value, not blur: kill drop shadows and stack three background values instead — base canvas, surface, and a raised surface — separated by a 1px hairline border at 8% white opacity (`box-shadow: none`, `1px solid rgba(255,255,255,8%)`). Hover changes which surface value is shown, not the elevation/shadow. Sheet shows literal hex swatches for canvas/list/hover backgrounds and a tag "elevation 0 → surface 2," captioned "flat surfaces look engineered, shadows look decorated."
- One color, used twice: indigo (or the single brand accent) appears only on the selected row and the primary button, nowhere else. Status is communicated with a grey icon, not a colored pill. Sheet shows a "7 colors" swatch row collapsing to "1 color," captioned "1 brand color · icons for status."
- Every action shows its keyboard shortcut next to it (e.g. C to create, Cmd+K to search). Hover feedback lands in about 80ms and transitions stay under 150ms with no bounce or overshoot — the UI visibly answers before the user finishes the gesture. Sheet renders a live Cmd+K command palette (typing "pri" → "Set priority" result) with the timing values printed directly on the frame: "80ms hover · 150ms max · 0 overshoot."
- A 4px grid governs the rest: 16px icons centered on the text line, labels left-aligned, numbers and dates right-aligned, nothing centered. Alignment is invisible when it's right and loud when it's wrong. Sheet shows a real issue row ("NOR-147 · Bulk edit for labels · Feature · Sep 4") with alignment guide lines confirming left/right placement, captioned "4px grid · 16px icons · numbers right."

DO / DON'T:
- Do: build depth from three stacked background values plus a hairline border (rgba white at 8%), and change the surface value on hover.
- Do: print the keyboard shortcut next to every action, and keep hover feedback near 80ms with transitions under 150ms.
- Do: left-align labels and ids, right-align numbers and dates, and center icons on the text line using a 4px grid.
- Don't: use drop shadows to separate rows, panels, or the sidebar.
- Don't: encode status or priority with colored pills when a grey icon says the same thing.
- Don't: let transitions bounce, overshoot, or drag past 150ms.

VIDEO ADDS: The whole pattern is framed as "Five decisions. No designer." walked through as a tabbed progression (Density / Borders / One color / Keyboard / Alignment) with a literal "2/5 decisions" progress indicator, each decision demonstrated on the same realistic issue-tracker mockup rather than abstract examples — a rendered list with real-looking rows ("Migrate billing webhooks to v2," "NOR-147 Bulk edit for labels"); exact hex-style color tokens shown for canvas/list/hover backgrounds and the `box-shadow: none / 1px solid rgba(255,255,255,8%)` CSS line printed on-frame; a direct "✓ engineered" vs "✗ decorative" verdict tag on the shadow-vs-border comparison; a live Cmd+K palette interaction with the 80ms/150ms timing values printed on the frame itself; and literal alignment guide lines drawn over a real row to prove the 4px grid, none of which the text states with this level of precision.

KLADRA: This is close to a direct style-reference for Kladra's whole information-density surfaces — the companies/projects/quotations/dispatches lists, the coordinator's queue, and any table-like view are exactly the row-density, flat-surface, one-accent-color context this pattern targets. Concrete transferable numbers: keep hover feedback near instant (Kladra's own rule is 100ms for hover/menus, close to this pattern's 80ms) and dialog/drawer transitions inside 150-250ms (Kladra's stated budget already brackets this pattern's "under 150ms, no overshoot" rule) — no tension, just confirmation. The "one color used twice" and "status as a grey icon, not a colored pill" rules reinforce Kladra's own "every state has a word, never colour alone" rule almost exactly. CONFLICT: Kladra's standing decision is "exactly two gradients (the primary action and the logo mark)" — this pattern's flat, gradient-free depth-via-background-values approach is compatible with that (it doesn't ask for more gradients), so no real conflict, but note the pattern's own recommended depth technique (stacked flat surfaces, zero shadows) is stricter than Kladra needs to be since Kladra already permits shadows/borders per DESIGN.md — treat "kill all shadows" as optional, not mandatory. The keyboard-shortcut-everywhere convention (C to create, Cmd+K to search) is a strong fit for Kladra's search palette if one exists, and reinforces adding visible shortcut hints to primary list/board actions.

PRIORITY: high — density, flat surfaces over shadows, one accent color, and printed keyboard shortcuts are all directly applicable to Kladra's list/queue/dashboard surfaces and align tightly with existing motion-timing and color-restraint rules already in CLAUDE.md, making this one of the more actionable references for the front-end re-audit.
