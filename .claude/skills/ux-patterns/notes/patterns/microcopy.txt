TITLE: Microcopy
CATEGORY: Content
URL: https://designmotionhq.com/patterns/microcopy

PROBLEM: The same form with the same layout converts very differently depending on word choice alone — system-speak in labels, errors and empty states reads as hostile or robotic and measurably costs conversions/usability.

RULES:
- Button labels should name the reward, not the mechanic: "Create my free account" feels like a gift being given; "Submit" feels like a chore being demanded — same underlying action, different framing. Video shows a measured outcome: "Submit" converts at 19% vs "Create my free account" at 91% on the identical form.
- Turn errors into help, not a dead end: "Invalid input" tells the user nothing actionable; "That email's taken — want to log in?" names the specific problem and immediately offers the next move (a link). Framed as "a detour, not a dead end."
- Empty states are onboarding, not a void: instead of a blank inbox, show the first step the user can take right now (e.g. "No messages yet" + a "Compose" button) rather than leaving a blank screen with no path forward. Framed as "teach the first action."
- Placeholder text is not a label: it vanishes the instant the user starts typing, leaving the field unidentified once populated — keep a persistent label above/beside the input at all times, don't rely on placeholder-as-label. Framed as "the question vanished the moment they typed."
- Write like a person, in the product's own voice: no real human says "operation failed" — replace system-speak error/status text with a phrase a helpful colleague would actually say (e.g. "Hmm, that didn't go through — try again?"). Framed as "words carry the brand."
- Copy carries as much functional weight as layout: labels, errors, empty states and tone collectively decide whether an interface feels usable or hostile — it's not decorative, it's structural.

DO / DON'T:
- Do: label actions with the reward the user gets ("Create my free account"), not the system verb ("Submit").
- Do: turn error messages into a next step ("That email's taken — want to log in?").
- Do: fill empty states with the first useful action, not a blank screen.
- Don't: rely on placeholder text as a stand-in for a persistent field label.
- Don't: ship system-speak like "Invalid input" or "operation failed."

The error-message panel shows the actual field state: "Email address" input containing "you@example.com" with the helper text "That email's taken — want to log in?" where "want to log in?" is a live inline link, not just plain text. Closing frame: "Words ship conversion" with the winning CTA button rendered large plus "Follow for more UX writing" and "Save this for your next form."

KLADRA: Applies across every form, dialog and empty state in Kladra — quotation/dispatch/project request dialogs, the record drawers, list/board empty states, and toast/error copy — and must be done in both locales per CLAUDE.md's "both locales ship together" rule, so any reward-framed button label or humanized error string needs an equally considered Arabic equivalent, not a literal translation (this is `.claude/rules/words.md` territory). Concrete uses: (1) button labels across Kladra (e.g. "Create quotation," "Send dispatch") should already read as the outcome, not a raw verb — worth auditing for any leftover "Submit"/"Save" labels; (2) error copy on server-action failures should name the problem and the next step, not surface raw error text; (3) empty states on companies/projects/quotations/dispatches lists and the coordinator's queue should show the first action (e.g. "No quotations yet — Create one") rather than a blank list, which doubles as a natural, allowed substitute for tools Kladra explicitly forbids (no saved views to browse into, so the empty state itself must teach); (4) never rely on placeholder-only fields — Kladra's forms should keep persistent labels above inputs, which also matters for RTL since placeholder-only Arabic fields have the same "vanishes on type" problem plus bidi/alignment issues; (5) tone should stay one deliberate voice — plain, direct, "sales rep obvious" per CLAUDE.md's own decision-making instruction — not necessarily as casual as "Hmm, that didn't go through," but definitely not raw system-speak like "operation failed." No conflict with standing Kladra rules; this is pure content/copy discipline orthogonal to drag-and-drop, bulk edit, motion timing, or gradients.

PRIORITY: high — microcopy touches literally every screen (labels, errors, empty states, button text) in both English and Arabic, is cheap to fix relative to layout work, and directly reinforces Kladra's own "words.md" glossary discipline and "every state has a word" principle already in CLAUDE.md.
