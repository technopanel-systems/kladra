TITLE: Design System Kit
CATEGORY: visual
URL: https://designmotionhq.com/patterns/design-system-kit

PROBLEM: Random hex values and eyeballed pixel gaps don't scale across a product — only a named-token system does.

RULES:
- Swap hardcoded hex for semantic tokens (`var(--brand)`, `var(--error)`) — intent survives every redesign, and a single rename updates the whole app (video shows raw `color: #7C3AED` replaced by `color: var(--brand)`, etc., with a green checkmark once tokenized).
- Build a numbered color scale (100–900) so every shade is systematic, then map it to semantic names (brand, success, error) — video shows a 9-step primary scale (900→100) plus 4 semantic swatches (bg-primary, brand, success, error).
- Define a fixed type scale with set sizes/weights (video lists six steps: 36px/700 text-4xl down to 12px/400 text-base) — same size/weight everywhere kills hierarchy.
- Base spacing on a 4px scale: space-1=4px up to space-16=64px (video shows 6 steps: 4/8/12/16/24/32/48px labeled space-1 through space-12). Random gaps (7px, 23px, 11px) read as sloppy.
- Standardize components as variants × sizes × states: Primary/Secondary/Ghost/Destructive buttons, Small/Medium/Large sizes, Default/Focus/Error/Disabled inputs (video shows exactly this button/input matrix plus a sample card with New/Active/Pending/Error status chips).
- Match motion to intent and keep a duration scale: ease-out to enter, ease-in-out to move, ease-in to exit; 100ms micro-interactions (hover, toggle) up to 500ms complex transitions (video lists 100/200/300/400/500ms mapped to micro/small/medium/large/XL).

DO / DON'T:
- Do: store every value as a named token so color, type, spacing stay consistent app-wide.
- Do: build numbered scales (color 100–900, spacing 4→64) so choices are systematic.
- Do: tie easing and duration to the interaction's intent.
- Don't: hardcode raw hex or pixel values inline.
- Don't: pick spacing by eye.
- Don't: give every text the same size and weight.
